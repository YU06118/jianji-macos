# 简记 · macOS 热更新（自动更新）设计与使用说明

> 版本：v1.1（2026-11-21） ｜ 适用：简记 macOS 版 0.1.8 及以上
> 机制：Tauri v2 官方 `tauri-plugin-updater`（minisign 签名校验 + 替换 `.app` 后自动重启）

## 一、用户视角：如何工作

1. **只需安装一次**：从 Release 页下载与机型匹配的 `jianji_0.1.8_x64.dmg`（Intel）或 `jianji_0.1.8_aarch64.dmg`（Apple Silicon），把「简记.app」拖入 `/Applications`。
2. **自动检查**：启动约 3 秒后在后台静默检查新版本；发现新版会弹窗询问「立即下载并安装？」，确认后自动下载（toast 显示进度）→ 安装 → 自动重启到新版。
3. **手动检查**：设置页 →「检查更新 → 立即检查」。
4. **可调项**（设置页）：
   - 自动检查更新：开/关（持久化到本机数据库 `auto_update_check`）
   - 更新下载源：自动 / 官方 GitHub / 国内镜像（持久化到 `update_source`；镜像未配置时选择会提示未开通）
5. **失败安全**：下载中断、签名校验失败、安装失败 → 新版不会进入安装环节，**旧版完好可继续使用**，重试即可。

## 二、安全模型

| 环节 | 机制 |
|---|---|
| 更新源 | HTTPS 强制；latest.json 先整体校验、再比较版本号 |
| 更新包完整性 | minisign 数字签名：公钥内嵌于应用（`tauri.conf.json → plugins.updater.pubkey`），签名随包发布（`.sig` → latest.json 的 `signature` 字段），验签不过即中止 |
| 版本升级 | 只认更高版本号（SemVer），不会误降级/重装同版本 |
| 用户数据 | SQLite 位于 `~/Library/Application Support/com.jianji.ledger/`，与程序目录分离，更新/重装均不丢数据 |

**私钥保管**：`~/.tauri/jianji.key`（本机）+ GitHub 仓库 Secrets `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。私钥沿用原 minisign 密钥。**私钥或密码丢失将无法再签发可用更新**，只能重新发布需要手动安装的新版本。

> minisign 签名只保证更新包完整性与来源，**不代表 Apple 代码签名或公证**；应用本身为未签名构建。

## 三、更新源与 latest.json

```
应用内端点（tauri.conf.json → plugins.updater.endpoints）：
  https://github.com/YU06118/jianji-macos/releases/latest/download/latest.json
```

- latest.json 格式：

  ```json
  {
    "version": "0.1.8",
    "notes": "详见 Release 页",
    "pub_date": "2026-11-21T00:00:00Z",
    "platforms": {
      "darwin-x86_64":  { "signature": "…", "url": "https://github.com/YU06118/jianji-macos/releases/download/v0.1.8/jianji_0.1.8_x64.app.tar.gz" },
      "darwin-aarch64": { "signature": "…", "url": "https://github.com/YU06118/jianji-macos/releases/download/v0.1.8/jianji_0.1.8_aarch64.app.tar.gz" }
    }
  }
  ```

- 平台键固定为 `darwin-x86_64`（Intel）与 `darwin-aarch64`（Apple Silicon）；`signature` 为 minisign 签名**内容**（非路径）。
- Release 资产名必须精确为 `latest.json`，由 CI 每次发版覆盖为最新版。
- 更新包为 `.app.tar.gz`（不是 DMG）；DMG 只用于首次安装/手动重装。

## 四、发布 SOP（发新版）

1. 改版本号三处：`desktop/src-tauri/tauri.conf.json`、`desktop/src-tauri/Cargo.toml`、`desktop/package.json` → commit
2. `git tag vX.Y.Z && git push origin main vX.Y.Z`
3. CI 自动完成（`.github/workflows/macos-release.yml`）：
   - `Build macOS` 矩阵任务在 `macos-14` 上分别构建 `x86_64-apple-darwin` 与 `aarch64-apple-darwin`，使用 Secrets 完成 minisign 签名；
   - `Publish Release` 汇总 artifacts，重命名为 ASCII（`jianji_<version>_x64.*` / `jianji_<version>_aarch64.*`），生成 `latest.json`，创建或复用 Release 并上传：
     - 2 个 DMG、2 个 `.app.tar.gz`、2 个 `.sig`、`latest.json`；
   - Release 说明自动附带「应用未签名，首次打开右键 → 打开」「自动更新需放入 /Applications」。
   - 手动触发 `workflow_dispatch` 只上传 Actions artifacts，**不发布 Release**。
4. 验收：
   - `https://github.com/YU06118/jianji-macos/releases/latest/download/latest.json` 可访问，且同时含 `darwin-x86_64` 与 `darwin-aarch64` 条目；
   - 在 `/Applications` 中已安装旧版，触发「立即检查」，走完整下载→验签→安装→重启流程；
   - 两个架构的 DMG 均可正常挂载与打开。

## 五、回滚预案

| 场景 | 处置 |
|---|---|
| 下载/验签/安装失败 | 无需处理：旧版完好，用户重试即可 |
| 新版发布后出现严重 bug | **止血**：删除该 Release 的 `latest.json` 资产（阻止后续用户升级）；不能靠把版本号改回旧值来降级——已升级用户不会自动回退 |
| 已升级用户恢复 | 手动下载上一版 DMG，把「简记.app」覆盖到 `/Applications`（数据不丢） |
| 正式修复 | 发布 hotfix：版本号 +1（patch 位），走正常发布 SOP |

**设计取舍**：不实现「自动回滚到上一版」——Tauri 无内置支持，自研成本远超收益；本应用数据层为本地 SQLite 且与程序目录分离，版本兼容风险低，另有 JSON 备份兜底。

## 六、已知限制与说明

- **未签名 / 未公证**：未配置 Apple Developer ID，首次打开需右键 →「打开」或执行 `xattr -dr com.apple.quarantine "/Applications/简记.app"`；Gatekeeper 可能提示「无法验证开发者」，属于预期行为。
- **必须在 /Applications 下**：自动更新会替换应用包；从 DMG 直接运行或放在其他目录时安装会失败，请先把「简记.app」拖入 `/Applications`。
- **无二进制差量**：每次下载完整 `.app.tar.gz`，记账工具低频发版，可接受；如未来需要差量再评估 bsdiff 类方案。
- **首版种子**：0.1.8 是 macOS 版首个发布版本，需要手动安装这一次；之后可由更新器自动升级。
- **不要用 dev 模式验证安装环节**：`tauri dev` 的路径与生产不同；端到端验证一律用构建出的产物。
- **更新源已统一**：官方源常量已统一为 `jianji-macos`，自动/官方/镜像三种选择均指向本仓库发布通道。
